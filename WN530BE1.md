# WAVLINK WN530BE1-A Router

**Vendor**: WAVLINK

**Product**: WL-WN530BE1-A

**Firmware Version**: M30BE1_V251117

**Vulnerability Type**: Unauthenticated Command Injection

## Description

When the `ioos` binary processes requests to `/protocol.csp?opt=wireguard_cli_group&function=set&action=add`, the `sub_27B20` function concatenates the user-controlled `group_name` parameter into a `system()` call via `snprintf()` without any sanitization. The parameter value is wrapped in single quotes and executed directly as a shell command.The ioos binary extracts the IP-FROM field from the HTTP request header and assigns it to con->ip_from. The con_check_read_finish function then evaluates whether con->ip_from equals "127.0.0.1" to decide whether to skip the login verification process. However, because con->ip_from originates from a client-supplied HTTP header rather than the actual TCP socket peer address, an attacker can trivially forge IP-FROM: 127.0.0.1 to bypass all authentication checks without any credentials.

## Impact

This vulnerability allows an attacker with network access to the device to:

1. **Full Device Compromise**: Execute arbitrary commands as root and obtain an interactive shell.
2. **Data Exfiltration**: Read sensitive files such as `/etc/shadow`, Wi-Fi credentials, and VPN certificates.
3. **No Authentication Required**: Exploitation requires no credentials when combined with the `IP-FROM: 127.0.0.1` header authentication bypass.

The `ioos` binary reads the `IP-FROM` HTTP request header and stores its value in `con->ip_from`. The `con_check_read_finish` function checks whether `con->ip_from == "127.0.0.1"` to decide whether to bypass login verification. Since `con->ip_from` is derived from a client-supplied HTTP header rather than the actual TCP socket peer address, an attacker can forge the `IP-FROM: 127.0.0.1` header to bypass all authentication.
